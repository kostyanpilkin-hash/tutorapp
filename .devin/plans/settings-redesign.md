## C. Новые настройки (коммит на каждую группу)

Каждая — отдельным коммитом; ключи в таблице `settings`, чтение/запись через существующий `get_settings`/`set_setting` + `api.setSetting`. Дефолты должны совпадать с текущим поведением, чтобы без настройки ничего не менялось.

### C1. Настройки бота в UI (раздел «Интеграции»)

Сейчас редактируются только через inline-меню бота — те же ключи, общая таблица, конфликтов нет:
- `tg_fields` — чекбоксы полей карточки занятия: `student, time, link, subject, duration, notes, payment, cost` (список из `telegram/handlers.rs::FIELD_CHOICES`); значение — CSV как у бота. Внимание: `time`/`student` у бота обязательны — сверить с `settings_markup`, не давать выключить обязательные.
- `tg_offsets` — чекбоксы интервалов из `REMINDER_OPTIONS` (1440/60/30/15/5/0) → CSV минут.

### C2. Дайджест и тихие часы

- `tg_digest_time` (дефолт `09:00`, `""` = выкл) — в `jobs.rs` заменить `hour()==9 && minute()<30` на окно `[time, time+30min)`; выключенный дайджест пропускается.
- `tg_quiet_from`/`tg_quiet_to` (дефолты 23 и 7) — `quiet_now` в `telegram/mod.rs` читает настройки; интервал через полночь (23→7) и обычный (например 13→15) — оба должны работать.

### C3. Мелкие настройки

- `default_page` (`home`/`calendar`) — стартовая страница: `App.tsx` инициализирует `page` из настройки после `load()`.
- `default_currency` — валюта по умолчанию для новых учеников в `StudentFormDialog` (у Student уже есть `default_currency`, приложение дефолта не знает).

### C4. Опционально (только если быстро)

- `week_start` (пн/вс) — сначала проверить, где считается начало недели (`defaultRange`, WeekView, `date-fns` locale); если разбросано — пропустить.
- Автобэкап `auto_backup_enabled`+`auto_backup_dir` — при старте app копировать БД раз в N дней; отдельная оценка.
