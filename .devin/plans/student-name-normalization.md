# student_name normalization

## Статус: к исполнению (новый тред, первая задача)

## Проблема

`lessons.student_name` — денормализованная строка. Переименование ученика в `students` не обновляет занятия: старые уроки, история, финансы, бот и телефонная страница показывают старое имя.

## Подход (без миграции данных — меняем только чтение)

Имя для отображения резолвить через `lesson_students → students` (JOIN): имя = имена связанных учеников. Колонку `student_name` НЕ удалять в этой волне — оставить как fallback для осиротевших занятий (все ученики отвязаны/удалены) и для отката.

- Бэкап `tutor.db` перед деплоем установленной версии — на всякий случай (данные не меняются, но правило «миграция+бэкап» соблюдаем).
- `student_name` продолжает писаться при create/update (совместимость, откат тривиален).

## Шаги

1. Аудит всех чтений `l.student_name`: `row_to_lesson`/SELECT-списки в `lessons/repo.rs`, `Occ.name` в `occurrences.rs`, `expanded_lessons_in_range`, телефонная страница (`http_server.rs`), Telegram (`telegram/`), finance entries, `load_lesson_by_id`.
2. Реализовать резолв: для каждого занятия брать имена `lesson_students JOIN students` (ORDER BY сохранить детерминированным), склеивать как сейчас (проверить текущий формат `student_names()` в repo.rs — вероятно «, »); fallback — `l.student_name`, если учеников нет.
3. Подменить источник имени во всех найденных местах (единый хелпер в `repo.rs`, чтобы не разъезжалось).
4. Снапшот-дифф на копии реальной БД (по образцу `finance_report_dump_real_db`/parity): список занятий `[id, startAt, studentName]` до/после — идентичен, кроме случаев, где student_name уже устарел (показать дифф пользователю).
5. Тест: переименование ученика в `students` → новое имя видно в `get_lessons`/expanded/Occ без правки занятий; осиротевшее занятие (нет lesson_students) показывает `student_name`.
6. `/verify` → changelog → коммит → пуш.

## Критерий приёмки

- Переименование ученика мгновенно отражается на всех занятиях/истории/боте/телефоне.
- Осиротевшие занятия показывают сохранённое имя.
- Дифф на реальной БД пуст либо только исправленные имена.
